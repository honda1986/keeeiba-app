# keeeiba-app

中央競馬のその日の全レースから「買う価値のあるレース」(2強のレース)だけを選んで、◎○と買い目を出すアプリ。

**2026-10-21 から中央だけに絞った**(地方は取らない・予想しない・収支に出さない)。`keiba.CENTERS`(環境変数
`KEIBA_CENTERS`。既定 `jra`)で切り替える。地方の昔の記録と、下の地方の分析はファイルに残してある。

**投票タブ**(2026-10-23〜): その日の買い目を発走順に並べ、締切(発走2分前の目安)までの時間を出す。
1件ずつ/発走前の分をまとめてコピーできる(このアプリでは買わない。投票は即PAT・A-PATなどで自分で)。
自分で買ったら「買った」を押すと、結果が出たあとに自分の収支を出す(記録はその端末のブラウザにだけ残る)。
「買い目を作る」(投票タブ・レースのカード・見送りの行)で、予想に無いレースや券種も入れられる:
単勝・複勝・枠連・馬連・ワイド・馬単・3連複・3連単、通常・ボックス・ながし(軸1頭。馬単・3連単は軸が1着)・
フォーメーション(列ごとに選ぶ。馬単・3連単は1着・2着・3着の列)。
中央の開催日は「競馬の予想(開催日は10分ごと)」が、1回の実行の中で10分ごとに更新し続ける
(午前 8:31〜12:40、午後 12:31〜最後のレースの発走40分後。GitHub の時刻指定は遅れたり飛ばされたりするため)。
馬体重・取消・オッズを発走前の買い目に入れる。Androidアプリでは、開いたとき・「オッズ更新」で
発走前のレースのオッズを netkeiba からその場で取る(アプリが代わりに取る。予想アプリの表の人気・オッズだけ書き換える)。

**Androidアプリ(個人用、`android/`)**: 予想アプリを1画面で出す。オッズをその場で取るとき、
ブラウザからは netkeiba を読めないので、アプリが代わりに取る(race.netkeiba.com だけ)。
(2026-10-24 まであった IPAT の画面と自動入力は外した。)
「Androidアプリを作る」ワークフローが APK を作り、リリース「apk」に置く:
https://github.com/honda1986/keeeiba-app/releases/download/apk/keiba.apk
(署名の鍵 `android/keiba-personal.keystore` は個人用。同じ鍵なので上書きで更新できる)

中央は土日が中心で、出馬表は土曜分が木曜、日曜分が金曜に出る。毎日の更新では当日に加えて
明日・明後日の開催も先に取って予想しておく(`keiba.AHEAD_DAYS`)。アプリは、今日に中央の開催が無ければ
次の開催(無ければ最後の開催)を開く。

アプリ: https://honda1986.github.io/keeeiba-app/ (GitHub Pages を main ブランチで有効にする)

## 当日の馬場の偏り(試したが良くならない。2026-10-22)

同じ日・同じ場・同じ芝ダの、そのレースより前のレースの結果から偏りを出して材料にした
(3着内の内枠寄り − 出走馬全体の内枠寄り、3着内に占める「ふだん逃げ・先行の馬」の割合 − 出走馬に占める割合、
その馬が偏りに合うか、前の開催日(3日以内)の同じ偏り)。

- **偏りは続く**: 前のレース(3つ以上)で外枠が来ている日は、そのレースでも外半分の3着内率が内半分より4.3ポイント高い
  (内が来ている日は内が2.1ポイント高い、ふつうの日は差0.6ポイント)。脚質の偏りの続き方は小さい(±0.6ポイント)
- **それでもモデルは良くならない**: AUC 2024年 0.7997 → 0.7994 / 2025年 0.7965 → 0.7966 / 2026年 0.8000 → 0.8000
  (7R以降に絞っても同じ)。いちばん効く材料でも164個中51番目。回収率は今の基準 83% → 86%、○65%以上 90% → 90%。
  3年とも100%以上の基準は 492個中 0個。偏りは市場もすでに見ていると考えられる

## オッズも使って期待値で買う(試したが成り立たない。2026-10-22)

1着になる確率のモデル(3着内のモデルと同じ材料。月ごとにその月より前だけで学ぶ。2024年1月〜)を作り、
市場の確率(確定の単勝オッズから)と条件付きロジットで混ぜた(係数は月ごとにその月より前のレースで決める)。

- **混ぜる係数**: モデル 0.01〜0.03 / 市場 1.01〜1.03(2024年後半から)。ほぼ市場だけになる
- **1着の当たりやすさ**(対数尤度。2024年4月〜の8,488レース): モデル −2.061 / 市場 −1.919 / 混ぜる −1.919。
  混ぜても市場より良くならない = モデルには確定オッズ以上の情報がほとんど無い
- そのため期待値(確率 × オッズ)は払戻率の約0.8に張りつき、1を超える馬がほぼ出ない
- モデルだけの確率で期待値1以上の単勝を買うと 76〜81%(2024年4〜12月 73% / 2025年 83% / 2026年 78%)。
  市場と食い違う馬ほど負ける
- クラス(新馬・未勝利・1勝・2勝・3勝以上)・頭数・芝ダ・1番人気のオッズで分けて係数を決めても、
  2026年の対数尤度の差は ±0.005 以下(どの種類でも足す情報が無い)
- ワイドは、2頭とも3着内の確率を Harville で出して見積もりの期待値にしたが、1を超える組がほとんど出ない
- 勝つには、市場が値段に入れきれていない情報(調教・パドック・オッズの動き・券種ごとのオッズのずれなど)が要る

## 2024年も確かめた: どの年もそろって100%を超える買い方は無い(2026-10-22)

2022・2023年の中央のレースも取り込み(6,912レース)、2022〜2026年の5年分(16,028レース・22万頭)で学び直した。
月ごとの確率を **2024年1月から** 作り(各月はその月より前の2年以上で学ぶ)、2024・2025・2026年の3年で確かめた。
AUC は 2026年9月〜で 0.778(3年分で学んだときと同じ)。

| ワイド◎-○ | 2024年 | 2025年 | 2026年1〜8月 | 2026年9月〜 | 計 |
|---|---|---|---|---|---|
| 全レース | 89% | 83% | 80% | 93% | 85%(5,786R) |
| 今の基準 ◎60%以上・○40〜50% | 76% | 82% | 91% | 111% | 83%(887R) |
| ○60%以上 | 89% | 86% | 83% | 90% | 86%(822R) |
| ○65%以上 | 90% | 89% | 94% | 78% | 90%(430R) |
| 今の基準で、発走時10℃未満を見送り | 84% | 86% | 92% | 111% | 88%(724R) |

- 3年分で学んだモデルで 2025年 107% だった今の基準は、5年分で学ぶと 82%。モデルが少し変わるだけで動く程度の差だった
- ◎の下限と○の帯の組み合わせ 494 個のうち、3年ともに100%以上のものは **0個**(いちばん良くて各年 93〜96%)
- 前の年までで選んだ上位の基準を次の年で確かめると、平均 70%(2025年)・87%(2026年)
- 3年でそろった傾向は「冬(1〜2月)・寒い日は悪い」だけ(1〜2月 45% / 83% / 73%、10℃未満 48% / 68% / 81%)。
  「雨・湿度が高いと良い」は2024・2025年には出なかった(雨 72% / 58%)
- ワイドの払戻率は約77.5%なので、85〜90%は当てずっぽうよりは良いが、市場に勝つには足りない

### 気温・湿度・天候(試したが採らなかった。2026-10-22)

`tools/fetch_weather.py` で中央10場の場所の1時間ごとの気温・湿度・雨量・天気を Open-Meteo(CC BY 4.0)から取り、
`keiba_weather.json`(2022年〜。「気象データを取る」ワークフロー)に貯めた。`keiba_weather.py` で
発走のころの気温・湿度・天気・朝からの雨量と、各馬の過去走のときの気温・暑い日/寒い日/雨の日の着順の比を材料にした。

- **モデルの材料としては効かない**: AUC 0.7955 → 0.7959(同じ馬・2025年〜)。今の基準のワイドの回収率は 96% → 86%。
  `KEIBA_WX=1` で使える(既定は使わない)
- **買うレースを分けると**(今の基準・気象を入れないモデル): 冬(1〜2月)は両方の年で悪い(1月 61% / 56%、2月 90% / 28%)。
  発走時に10℃未満のレースを見送ると 96% → 102%(2025年 113% / 2026年1〜8月 92% / 9月〜 94%)。
  雨のときは 126% / 107% / 134%、湿度70%以上は 106% / 105% / 106%。たくさんの分け方の中から見つけたもので、
  偶然の可能性があるので、買う基準には入れていない

## 3着以内の確率モデル(2026年10月〜)

手作りの能力評価で選んだ◎○は市場(1・2番人気)より弱かったので、各馬が3着以内に来る確率を
LightGBM で学習させ、◎○と買うレースをそれで決めるようにした(`keiba_model.py`)。

- **材料**: 過去5走(着差・着順・クラス・通過順・上がり・その時の人気)、**馬場差で補正した走破タイム・上がり3Fの指数**、
  出馬表、騎手・厩舎のそれまでの3着内率、コース傾向、下の30か条の評価(能力・加減点・軸不可・消し)。
  そのレースのオッズは使わない(規則20)
- **◎○**: 軸にできる馬(延長などでない。規則15)のうち確率の上位2頭。相手は残りの上位2頭
- **買うレース**: 中央と地方は別物なので、基準を別々に決める(2026-10-19。`keiba_logic.MODEL_SELECT_FIXED`)。
  学び直しても変えない(None にすると学び直しで選ぶ)。基準に入らなければ見送り
  - **地方**: ○の確率が75%以上(80%以上はA)で、**9頭以上**のレース。8頭以下は◎○が3着内に来ても
    ワイドの配当が安く(当たったときの平均 119〜133円 / 9頭以上 135〜143円)、回収率が上がらない
  - **中央**: ◎の確率が60%以上で、○の確率が40〜50%(◎70%以上はA)。中央は○の確率で選んでも良くならない
    (○75%以上で 41R 81%)。○が強すぎるレースは人気どおりで配当が安く、◎がしっかりしていて○が抜けすぎていない
    レースだけ100%を超えた。ただし中央はレースが少なく、たまたまの可能性もあるので当日の成績で見直す
- **買い方**: ワイド◎-○の1点だけ(1レース100円)。2026年の再現で回収率がいちばん高かった
  (◎-○×5+相手4点 78% / ワイド1点 81% / 3連複・3連単・馬連を混ぜると 63〜65%)
- **確かめ方**: 月ごとに、その月より前だけで学んだモデルの確率(`keiba/model_wf.json.gz`)を作り、
  買うレースの基準は2〜8月で選び、9月〜で確かめた(基準を選ぶのに使っていない)。ワイド1点で:

  | 基準 | 2〜8月 | 9月〜 | 9月〜 同じレースの1・2番人気 |
  |---|---|---|---|
  | 中央・地方いっしょ ○70%以上 | 87%(939R) | 94%(179R) | 94% |
  | 中央・地方いっしょ ○75%以上 | 91%(509R) | 92%(96R) | 91% |
  | 地方 ○75%以上 | 92%(541R) | 98%(113R) | 101% |
  | 地方 ○75%以上・8頭以下 | 85%(219R) | 90%(48R) | |
  | **地方 ○75%以上・9頭以上(今)** | 96%(323R) | 104%(65R) | 108% |
  | **中央 ◎60%以上・○40〜50%(今)** | 111%(204R) | 125%(36R) | 105% |

  地方は○75%から上は回収率が横ばい(80%・85%でも同じくらいで、レースが減るだけ)。9頭以上に絞っても75%がいちばん良い
  (70% 88% / 94%、80% 96% / 100%)。月ごとでは 85〜106%。
  地方で試して採らなかったもの: 競馬場・馬場・クラス・距離・休み明けで絞る(グループが小さく、2つの期間でそろわない)、
  3連複◎○-▲△の2点(105%だが数回の大きな配当頼みで月ごとに 54〜139%)、騎手の乗り替わりをモデルに足す
  (AUC 0.8043 → 0.8046 で変わらない)、モデルを大きくする(変わらない)。
  中央は帯を2〜8月で選んだので、9月〜の36Rだけが本当の確かめ。中央と地方で別々のモデルも試したが、
  確率の当たり方(AUC)は1つのモデルと同じだったので、モデルは1つのまま
- **馬連も試した**(○70%以上のレース): 馬連◎-○の1点は 81% / 83%(2〜8月 / 9月〜)、
  馬連で確率1番を軸に2番・3番の2点は 86% / 76%。基準を選び直しても 82% / 82%、87% / 80% で、
  ワイド1点より低く、中央はどちらも悪い(37〜76%)ので採らない
- アプリの2026年の「再現」は、2月以降はこの月ごとの確率で予想している。先の結果を知ったモデルで
  過去の成績をよく見せないため。1月は手作りの評価
- 毎週月曜の朝に「モデルを学び直す」で新しい結果まで学び直す(基準は変えない)。
  手動で walkforward を on にすると、月ごとの確率と過去の日の予想も作り直す。
  学び直さずに基準の成績だけ出し直すときは `python tools/train_model.py --update-select`

### タイム指数(`keiba_speed.py`)

1kmあたりの走破タイムを「コースの基準(競馬場・芝ダ・距離)+クラスの差+その日の馬場差+馬の力」に分け、
馬柱に載っている過去走(同じ走りを1回に数えて約19万走。ほとんどが2025〜2026年)から基準・クラスの差・馬場差を交互に求める。
指数 =(基準+馬場差−タイム)×10。+10 で1kmあたり1秒速い。上がり3Fも同じように補正する。
馬場差はその日のタイムだけで決まるので、先の結果は使わない。表(`keiba_speed.json`)は学び直しのときに作り、
まだ表に無い日の馬場差は、当日の全レースの馬柱を取ったあとに足してから予想する。

指数を足すと、3着内の当てやすさ(AUC)は 0.781 → 0.793(市場は0.81)。
同じ基準(○60%以上)のワイド1点は、月ごとの確率で 2〜8月 80% → 85%、9月〜 83% → 83%(買えるレースが3割増え)。
効いている材料の1位は、指数の3走平均(レース内の順位)になった。

### 市場と食い違う馬(試したが採らなかった)

モデルの◎○が1・2番人気と違うレースで、違う馬に「はっきりした理由」があるものだけ残すのを試した
(`tools/check_disagree.py`)。理由は、タイム指数が人気馬より上・上がりの指数が上・人気馬に延長/昇級/休み明け/
斤量増/脚質の不利、など。厳しくしても(タイム差2以上かつ上がり差3以上、人気馬の減点2つ以上 など)、
理由のある食い違いのワイドは 9月〜で 61〜77% と、理由の無いものと変わらず、1・2番人気より悪かった。
モデルと1・2番人気が一致したレースだけ買うと 87% / 86%(2〜8月 / 9月〜)で、市場とほぼ同じ。
モデルは「どのレースを買うか」を選ぶのは得意だが、同じレースで2頭を選ぶのはまだ市場に届かない(特に中央)。

学び直し・確かめ: `python tools/train_model.py`(成績を出すだけ)/ `--save`(保存)/ `--walkforward`(月ごとの確率)。
買い方の比較: `python tools/simulate.py`。

## 流れ

1. 全レースから、強い2頭がいるレースだけを選ぶ(A / B)。1強・混戦・少頭数・新馬は見送り
2. 来ない馬の負け要因(距離・展開・枠・斤量・休み明け・クラス差・馬場・コース)で減点。重い減点が3つ重なった馬は消す
3. 残った馬から◎○を決める。距離延長の馬は軸にしない。◎○の弱点が同じ(両方逃げ・両方道悪苦手など)なら○を替え、替えられなければ見送り
4. 3連複は◎○2頭軸流し、3連単は◎⇄○の1・2着入れ替え
5. 馬連・ワイド◎-○で別の着順もカバーし、○-相手のワイドで◎が飛んだときに備える
6. 3頭目に人気薄(☆)を入れる

能力は過去5走の着差とクラスから作り、**人気・オッズは使わない**。オッズは評価ができたあとに
人気との食い違い(過剰人気? / 妙味)を見るだけ。アプリの全馬の評価の表には人気・オッズも出す。

閾値(2強の差・消しの基準・点数)は `keiba_logic.py` の `TH` にまとめてある。
「収支・分析」で条件別の回収率、印ごとの3着内率、減点理由ごとの3着内率(負けパターン)を見て締めていく。

| `keiba/index.html` | アプリ本体 |

発走を過ぎたレースの予想は書き換えない。収支は1点100円で、実際の払戻から計算する。

## 過去の日を見る

- **レース画面** … 日付を押すとカレンダーが開き、その日の予想・買い目・結果を見られる(◀ ▶ で前後の日)
- **収支・分析** … 期間(7日 / 30日 / 今月 / 今年 / 全期間)で絞って、累積収支・カレンダー・券種別・条件別・
  印の成績・負けパターン・日別・買ったレースの明細を見る。行を押すとその日・そのレースへ飛ぶ

アプリを動かす前の日は、Actions の「**過去の日を再現**」を手動でまわすと作れる(既定は2026年1月1日〜昨日)。
日付を最大20個のジョブに分けて同時に走らせ、各ジョブの中でも1日のレースを並列に取る
(netkeiba が混んだら待ってやり直す)。最後に1回だけまとめて保存する。
その日の出馬表と「そのレースより前の過去走」だけで予想し、結果・払戻と照合する。
済んだ日は飛ばすので、途中で止まってももう一度まわせば続きから再現する。

再現した予想には「再現」と印が付き、収支画面で「当日の予想」と分けて見られる。
再現では人気に確定人気を使う(当日の予想は朝〜発走前のオッズ)。人気は穴馬(☆)選びにしか使わないので、
◎○と買うレースの選び方は当日と同じ。

取得がおかしいときは Actions の「取得の診断」をまわすと、netkeiba の応答の形がログに出る(何も保存しない)。
ロジックや閾値を変えたら、Actions の「再現の予想を作り直す」をまわすと、保存してある馬柱から
再現の予想を今のロジックで作り直す(netkeiba からは取らない。当日の予想は書き換えない)。

## コース傾向(中央10場・78コース)

[titanic-online.com「競馬場の特徴」](https://www.titanic-online.com/category/racetrack/)の各記事
(2021〜2025年の集計)から、コースごとの脚質別・枠順別・人気別の成績と、
脚質傾向・枠順傾向・ペース傾向・向いている馬/向かない馬を `keiba_course.json` にまとめて使う。

- **脚質** … そのコースの逃げ・先行・中団・後方の3着内率を、芝/ダートの全コース平均と比べる
  (脚質はレース後に決まる位置取りなので、どこでも前の馬の成績が良く出る。平均との比で「このコースで得か」を見る)。
  得なら最大+3、損なら最大-4。大きな損は ◎○ の「弱点の重なり」にも数える
- **枠** … 枠番別の3着内率を平均と比べて±2.5まで(このとき一般の枠の決まりは使わない)
- **堅さ** … 1・2番人気の3着内率が平均より高い「堅い」コースは2強の基準を0.5下げ、「荒れやすい」コースは0.5上げて穴馬を2頭まで拾う
- 出走が少ないコースは平均に寄せて控えめに効かせる。記事に無い距離はその場の芝/ダート全体を半分の重みで使う
- 地方は下の「地方のコース傾向」

例: 新潟芝1000(千直)は8枠が平均の1.6倍・1枠が0.6倍。函館・小倉・福島のダ1700は後方が平均の半分以下。
東京芝2400・阪神芝1800は後方が1.7倍以上(差しが届く)。

作り直すとき: Actions の「記事を読む」(read)で記事の本文をログに出し、
`python tools/parse_course.py 出力.json 記事.txt ...` で取り出す(記事は海外からは読めないので Wayback Machine 経由)。

## 地方のコース傾向(14場・84コース。2026年10月〜)

[うまめし.com「地方競馬特徴･攻略･傾向」](https://www.umameshi.com/info/keibajou/chihou-keiba-hisshouhou.html)と、
そこからたどれる各競馬場・各距離の記事(地方14場の本文と97ページ)を読み、`keiba_course_nar.json` にまとめた。

- **数字** … 枠番別・人気別・脚質別(そのレースでの位置取り)の集計。記事によって人気別の「着外」が出走数そのものに
  なっているので、同じ行の複勝率に合う方を出走数にしている
- **説明** … 記事を読んで、各場・各距離の特徴を短くまとめたもの(記事の文をそのまま写したものではない)。アプリのコース傾向欄に出す
- **使い方** … 中央と同じ。脚質は地方全体の平均との比で加減点、枠は枠番別の3着内率の比で±2.5まで。
  記事に数字の無い距離は場全体の数字を使う(地方は場全体の枠の傾向も使い、一律の「地方の1枠 -2」は数字が無いときだけ)
- **場のずれ** … 同じ馬が別の場で続けて走ったときのタイム指数の差から、場ごとの目盛りのずれを求めて指数に足す
  (`keiba_speed.fit_levels`。記事の「地方競馬レベル順と力関係」「名古屋と笠松のタイム差」の考え方)。
  並びはおおむね 中央 > 大井・船橋 > 門別・川崎・園田・姫路・浦和・名古屋 > 佐賀・笠松・水沢・盛岡・金沢(高知は指数が低めに出る場で、上乗せが大きい)
- **移籍など** … 中央からの移籍(前走が中央)・中央を走った割合・前走と同じ場か・走った場の数・高知のファイナルレースをモデルの材料にする

記事から読み取ったおもな傾向: 川崎は内枠、船橋・園田1400・姫路・笠松・名古屋920/1500は外枠が有利。
浦和は逃げ切りが多く1600は外枠がとても不利。高知・佐賀はインの砂が深く1枠が不利(高知は2〜3枠が良い)。
盛岡は坂と長い直線で距離が延びるほど差しが届く。金沢は先行争いが激しい。門別は内枠がやや不利で、
冬の休み明け(開幕直後)は他場で使われていた馬が有利。

確かめ(月ごとに、その月より前だけで学んだモデル): 地方のAUC 0.797 → 0.804。
○75%以上のワイド1点は 2〜8月 509R 91% → 577R 91%、9月〜 96R 92% → 118R 96%(地方だけで98%)。

作り直すとき: Actions の「記事を読む」で links(リンク集め)と read(本文)をまわし、
`python tools/parse_course_nar.py keiba_course_nar.json 記事.txt ...`。`KEIBA_NAR_COURSE=0` で地方の傾向を切って比べられる
(切り替えたらモデルを学び直す)。
