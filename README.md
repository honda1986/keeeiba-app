# keeeiba-app

中央競馬のその日の全レースから「買う価値のあるレース」(◎が堅く、○とは差があるレース。2026-10-25 までは2強のレース)だけを選んで、◎○▲と買い目を出すアプリ。

**2026-10-21 から中央だけに絞った**(地方は取らない・予想しない・収支に出さない)。`keiba.CENTERS`(環境変数
`KEIBA_CENTERS`。既定 `jra`)で切り替える。地方の昔の記録と、下の地方の分析はファイルに残してある。

**投票タブ**(2026-10-23〜): その日の買い目を発走順に並べ、締切(発走2分前の目安)までの時間を出す。
1件ずつ/発走前の分をまとめてコピーでき、即PAT・A-PATを開くリンクがある(自動では買わない)。
自分で買ったら「買った」を押すと、結果が出たあとに自分の収支を出す(記録はその端末のブラウザにだけ残る)。
「買い目を作る」(投票タブ・レースのカード・見送りの行)で、予想に無いレースや券種も入れられる:
単勝・複勝・枠連・馬連・ワイド・馬単・3連複・3連単、通常・ボックス・ながし(軸1頭。馬単・3連単は軸が1着)・
フォーメーション(列ごとに選ぶ。馬単・3連単は1着・2着・3着の列)。
中央の開催日は「競馬の予想(開催日は10分ごと)」が、1回の実行の中で10分ごとに更新し続ける
(午前 8:31〜12:40、午後 12:31〜最後のレースの発走40分後。GitHub の時刻指定は遅れたり飛ばされたりするため)。
馬体重・取消・オッズを発走前の買い目に入れる。Androidアプリでは、開いたとき・「オッズ更新」で
発走前のレースのオッズを netkeiba からその場で取る(アプリが代わりに取る。予想アプリの表の人気・オッズだけ書き換える)。

**画面(2026-10-31 に見直し)**: 名前を「堅軸レース」に(◎が堅いレースだけ買う。前は「2強レース」)。
買うレースのカードに▲(3連複の3頭目)を出し、買い目にオッズを出す(3連複は ◎-○-x の組のオッズを、買うレースだけ
GitHub の更新とAndroidアプリの「オッズ更新」で取る。`trio_odds`)。「買い目を作る」はそのレースの今の買い目(3連複◎○▲、
▲が延長ならワイド◎-○)を入れた状態で開く。収支タブの「2強の差」別は「◎と○の差」別に。人気との見比べの札は
「過剰人気?」→「人気が上」、「妙味」→「人気が下」(妙味の馬は確率の見込みより来ない: 3着内 22% / 見込み 35%)。
考え方タブの印・評価・コースの堅さの説明を今の仕組みに合わせた。
「消し」の札と × の印はやめた(印と紛らわしく、買わない馬に見えるため)。負け要因が重なる馬は「負け要因が3つ重なる」
「能力差が大きい」の札だけ出し、行も薄くしない。印は確率の順だけで付け、札があっても印の付いた馬は買い目から外さない
(買うレースで札のある馬の3着内は ◎ 86% / 見込み 87%、○ 55% / 48%、▲ 46% / 41%、△ 29% / 29% と確率どおりかそれ以上)。

**Androidアプリ(個人用、`android/`)**(IPAT の画面と自動入力は 2026-10-24 に外し、**2026-11-11 に戻した**):
下の切り替えで「予想」(このアプリ)と「IPAT」(JRAのネット投票。投票ページは https://www.ipat.jra.go.jp/sp/ のスマホ版。
長押しでその場だけPC版に切り替えられるが、覚えておかず、起動のたびにスマホ版から開く。投票タブの「IPATを開く」のリンクも同じアドレス)を行き来する。
レースのカードの買い目(割安ワイド・モデルの買い目)・投票タブ・買い目を作るの「IPATで入力」で、IPAT(スマホ版)の画面を
通常投票 → 競馬場 → レース → 式別 → 方式 → 馬番 と押していき、**金額入力の画面で止まる**(`assets/autopilot.js`)。
2頭以上の券種は、どの買い方も IPAT のフォーメーション(1頭目・2頭目・3頭目の画面で馬番の行を押す)で入れ、
金額入力の画面で列ごとの馬番と組数が買い目と同じかを確かめる。単勝・複勝は1頭ずつ(馬を押すと金額入力へ)。
2点目からは投票一覧から続けて入れ、前と同じレース・券種なら「馬（枠）番から続けて入力」で競馬場・レースの画面を飛ばす。
馬番の画面では帯(「新潟(土) > 3R > ワイド」)が買い目と違えば選ばずに止める。押すのはアプリが指で押したのと同じように押す
(IPAT はスクリプトの click では進まない)。金額・セット・投票は自分で入れる(自動では買わない。ログイン情報はアプリでは持たない)。
IPAT を見ているときの「戻る」は予想に切り替えるだけ(IPAT が戻る・進むのボタンを使わないよう案内しているため)。
IPAT の上の赤い帯は、自動入力が止まったとき・金額入力の内容が買い目と違うときだけ出す。自動入力の途中で自分で画面に触ると止まる。
オッズをその場で取るとき、ブラウザからは netkeiba を読めないので、アプリが代わりに取る(race.netkeiba.com と AI競馬ナビ)。
予想の画面は起動のたびに読み直し、10分より長く裏に回っていたら戻ったときにも読み直す(GitHub Pages は10分キャッシュさせるため)。
「考え方」タブの下に、画面を置いた時刻とアプリの版と、新しい版(APK)を入れるリンクが出る。「IPATで入力」は IPAT の画面つきの版
(`KeibaApp.buy` がある版)でだけ出す。
「Androidアプリを作る」ワークフローが APK を作り、リリース「apk」に置く:
https://github.com/honda1986/keeeiba-app/releases/download/apk/keiba.apk
(署名の鍵 `android/keiba-personal.keystore` は個人用。同じ鍵なので上書きで更新できる)

中央は土日が中心で、出馬表は土曜分が木曜、日曜分が金曜に出る。毎日の更新では当日に加えて
明日・明後日の開催も先に取って予想しておく(`keiba.AHEAD_DAYS`)。アプリは、今日に中央の開催が無ければ
次の開催(無ければ最後の開催)を開く。

アプリ: https://honda1986.github.io/keeeiba-app/ (GitHub Pages を main ブランチで有効にする)

## 的中率を上げる: 堅い買い目(的中重視。2026-11-14)

「1着の的中率かワイドの的中率を上げたい」を確かめた(`tools/experiments/hit_rate.py`。2022〜2026年の中央 16,212レース、
モデルはその年を外して学び直したもの)。**的中率は上げられるが、回収率は上がらない(どの選び方も 80〜91%)。**

| 1着を当てる(単勝1点) | 的中 | 回収率 |
|---|---|---|
| 今の◎ | 27.6% | 79% |
| モデルの3着内の確率1位 | 29.5% | 80% |
| 1着を当てるモデル(学び直し) | 29.8% | 80% |
| 1番人気 | 33.7% | 80% |
| 1番人気が 2.0倍以下のレースだけ(全体の28%) | 48.5% | 80% |
| **1番人気が 1.8倍以下のレースだけ(19%)** | **53.0%** | 82% |
| 1番人気が 1.5倍以下のレースだけ(8%) | 62.9% | 86% |

| ワイドを当てる(1点) | 的中 | 回収率 |
|---|---|---|
| 今の◎-○ | 25.8% | 81% |
| 単勝の1・2番人気 | 32.2% | 81% |
| 3連複から見ていちばん来そうな組 | 32.7% | 80% |
| その組の確率が 40%以上のレースだけ(19%) | 55.8% | 87% |
| **その組の確率が 45%以上のレースだけ(12%)** | **60.4%** | 88% |
| その組の確率が 55%以上のレースだけ(4%) | 71.5% | 91% |

- **馬の選び方ではオッズに勝てない**: 1着もワイドも、モデルよりオッズ(1番人気・3連複から見た組の強さ)の方が当たる。
  1着を当てるモデルを作り直しても 29.8% で、1番人気の 33.7% に届かない。
- **効くのはレースの選び方**: 「堅いレースだけ買う」と的中率は 5〜7割まで上がる。ただし配当が安いので回収率は 80〜91% のまま。
- 3連複から見た確率(0.75 × その2頭を含む3連複の組の 1/オッズ の合計)は、実際より低めに出る(見込み 44.5% → 実際 50.2%、54.4% → 60.8%)。
  アプリの「見込み」は 1.12倍して出す。
- 1番人気が 1.8倍以下でも、モデルの確率1位が別の馬のレース(351R)は的中 45%・回収率 73%(同じ馬のレースは 54%・83%。5年とも低い)。
  アプリでは買い目の下に赤字で出す。

**アプリ**: これを「堅い買い目(的中重視)」として出す(`keiba_logic.SOLID`・`solid_win`・`solid_wide`、`keiba.solid_picks`・`solid_history`、
アプリの `SOLID`・`solidOf`。数字は `test_keiba.py` でそろえてある)。

- 単勝 … 1番人気の単勝オッズが 1.8倍以下のレースで、その馬
- ワイド … 3連複から見ていちばん来そうな組の確率が 45%以上のレースで、その組
- 当日は発走の30分前より後に取ったオッズで出す(それより前は出さない)。過去の日は確定オッズで選んだもの。
  「収支・分析」に、発走前のオッズで選んだ分の成績を別に出す(`history.json` の `solid` = 日ごとの
  [単勝の点数・的中・払戻、ワイドの点数・的中・払戻、発走前のオッズで選んだ点数・的中・払戻])
- 全レースの記録で数えると 単勝 3,249R・的中 52.6%・回収率 81.1%、ワイド 2,008R・的中 60.3%・回収率 87.5%
  (年ごとの的中: 単勝 55/51/53/50/55%、ワイド 57/59/59/67/60%)
- レースの欄・この日の買い目・次の買い目・投票タブ(「堅」の札)・収支・分析(1本目の線と表)・考え方に出す。
  割安ワイドは「収支・分析」の「くわしく」と「考え方」の下の方に移した(参考のまま)

## 高知の最終レースのアプリ(2026-11-07)

同じアプリのアドレスに `?site=kochi` を付ける(アプリの上の「高知へ」「中央へ」で切り替え。前に見た方を覚えている)。
高知競馬のその日の最終レース(ファイナルレース。20時台)だけを出す。**予想だけで、買う基準は付けない**。

- データ: 高知の全レース(2023年〜。4,500R)を `keiba/kochi` に取る(`KEIBA_OUT=keiba/kochi`・`KEIBA_CENTERS=nar`・
  `KEIBA_NAR_VENUES=高知`)。モデルは高知のレースだけで学ぶ(`KEIBA_MODEL_TAG=kochi` → `keiba_model_kochi.txt`)。
  「高知の予想(最終レース)」(`keiba_kochi.yml`)が朝・昼に予想し、開催日の 15:41 から最後のレースの結果まで10分ごとに更新する。
  「過去の日を再現」「モデルを学び直す」「再現の予想を作り直す」は site=kochi で高知
- モデルの当たり方(AUC): 試験期間 0.828(市場 0.812)。高知の全レースでは確率どおりに来る(◎ 実際 71% / 見込み 73%)
- **最終レースは確率ほど来ない**: ◎ 44% / 51%、○ 34% / 41%(2024〜2026年の最終レース 273R)。いちばん下のクラスで荒れやすい
- **勝てる買い方が無い**(`tools/experiments/kochi_final.py`): 最終レースを全部買うと 複勝◎ 82%・ワイド◎-○ 71%・単勝◎ 68%・
  3連複◎○▲ 46%。2024・2025年で回収率の高い券種・条件を選んでも2026年に続かない(171% → 30% など。相関 0.01)。
  高知の全レースで選んでも「◎85%以上の複勝◎」の 94〜95% がいちばん良い。そのため予想だけ(`KEIBA_PREDICT_ONLY=1`)
- **最終レースは別の確率で予想する**(`keiba_final.py`・`tools/kochi_final_fit.py`・`tools/experiments/kochi_final_model.py`):
  最終レースは荒れる(1番人気が3着内 54% / ほかのレース 78%、3着内に7番人気以下 67% / 27%、3連複の配当の中央 8,780円 / 1,490円)。
  そこでは今のモデルより単勝オッズの方が当たる(AUC 0.645 / 0.695)。単勝オッズから出した3着内の確率(Harville)に、今のモデルの確率と
  前走(着順・人気・着差・近3走の最高着順・通過順・クラスの差・休み・距離の差・馬体重の増減・枠)を足したロジスティック回帰を
  最終レースだけで学び(`keiba/kochi/final_model.json`。毎週の学び直しで作り直す)、その確率の順に ◎○▲△ を付け直す(AUC 0.699)。
  ◎ 54%・○ 42%・▲ 38%・△ 31% が3着内(前の印は ◎ 40〜44%)で、確率の見込みとも合う。オッズが出る前(朝・昼)は今のモデルのまま。
  買い方は、年ごとに分けて確かめても 複勝◎ 92%・ワイド◎-○ 80%・3連複◎○▲ 123%(当たり 17/305、大きい3つを除くと 84%)で、予想だけのまま
- **荒れ度**(`keiba_final.chaos`。式は `final_model.json` の chaos): 1番人気のオッズとオッズのばらけ方から、1番人気が3着に来ない確率。
  1番人気が 3.3倍以下なら3着外 29%、4.1倍以上なら 61%(3年ともそろう)。高(55%以上)と読んだレースは実際 50〜68%、低(40%未満)は 10〜40%。
  荒れると読んだレースで人気薄(ワイド4〜6番人気BOX・複勝7〜9番人気など)を買っても 59〜84%
- **機械学習で人気の見落としを探す**(`tools/experiments/kochi_ai.py`): 過去5走の中身(着順・人気・着差・通過順と上がり・クラスや距離や場の変化・
  人気より上の着順の回数・調子の上下)・騎手と厩舎の、そのレースより前の成績・馬体重・休み・枠など35の特徴を LightGBM で。最終レースの
  AUC 0.698(最終レース用の式 0.699、単勝オッズだけ 0.691)で良くならない。効くのはほとんどオッズと今のモデル。
  機械学習の確率がオッズの見込みの1.5倍以上の6番人気以下は、3年とも見込みより来る(12% / 8%)が、オッズの見込み(Harville)が人気薄を
  低く見る分で、複勝は 77〜84%

## 高知で分かったことを中央に(買い方は変えない。荒れ度は参考に出す。2026-11-07)

`tools/experiments/jra_chaos.py`。荒れ度の式は 2022〜2025年で決め、成績は 2024〜2026年で年ごとに見る。

- **オッズを混ぜた確率で印を付け直す**: 高知の最終レースで効いたのは、そこでは今のモデルがオッズより当たらないから。
  中央のモデルはオッズとほぼ同じだけ当たり、勝てているのは ▲ を人気と違う選び方で拾えている分(◎○▲が1〜3番人気と違う 127% / 同じ 91%)。
  前に ▲ を「確率×市場」で選んだときも 112% → 99% に下がった。オッズを混ぜると強みが消えるので使わない
- **荒れ度は中央でも読める**: 1番人気が3着に来なかった率は、荒れ度 20%未満 13%・20〜30% 26%・30〜40% 35%・40〜55% 46%・55%以上 57%
  (見込みとの差は数%で、2022〜2026年のどの年もそろう)
- **買うレースは荒れ度で分けても変わらない**: 買うレースは ◎ が1番人気(595R / 627R)で、荒れ度はほとんど 30%未満。
  荒れ度で4つに分けると 今の買い方 137%・131%・120%・127% で、年ごとの上下は入れ替わる。3連複とワイドのどちらが良いかも荒れ度では決まらない
- **見送りレースにも勝てる買い方は無い**: 荒れ度(30%未満・30〜45%・45%以上)と ◎ の人気(1番人気か)で6つに分けても、
  単勝◎ 76〜87%・ワイド◎-○ 79〜90%・3連複◎○▲ 65〜97% で、年をまたいで 100% を超えるところは無い
- **荒れ度はアプリに出す(参考)**: 中央の各レースに「荒れ度 低/中/高 ○%: 1番人気(○番)が3着に来ない確率」を出す
  (買うレースはカードの上、見送りは1行に「荒れ低/中/高」と、開いた中に)。結果が出たレースは確定オッズ、それまでは今のオッズ
  (アプリでオッズを取り直せばその分)で、アプリの中で計算する。式は `keiba/chaos_model.json`(`tools/chaos_fit.py`。中央 2022年〜の
  16,778R。毎週の学び直しで作り直す)。段は高知と同じ(高 55%以上・中 40%以上・低)。「考え方」に段ごとの実際の率を出す

## 単勝5倍以上の馬が勝つときの特徴(2026-11-08)

`tools/experiments/longshot_win.py`。中央 2022〜2026年 16,212R(障害を除く)、5倍以上の馬 191,482頭。天気は `keiba_weather.json`(Open-Meteo)。
「見込み」は単勝オッズから見込む勝つ率(レースの中で 1/オッズ を合計1にそろえる)。実/見 が 1 より大きいとオッズより勝っている。

- **5倍以上が勝つレースは、オッズでもう分かっている**: 5倍以上の馬が勝ったレースは 46%(見込み 47%)。多いのは 1番人気が4倍以上 72%
  (1.9倍以下は 36%)、17〜18頭 56%(10頭以下 32%)、ハンデ 58%、G3 59%、11R 58%、福島 53%・小倉 51%(東京 42%)。少ないのは 2歳 39%・
  新馬と未勝利 43%。馬場・天気・気温・雨量・季節ではほとんど変わらない(45〜50%)。どれもオッズの見込みとほぼ同じ(実/見 0.94〜1.02)で、
  東京だけ5年とも見込みより少し少ない(0.92〜0.96)
- **5倍以上のどんな馬がオッズより勝つか**(5年ともそろうもの): 多い = 10〜19.9倍(1.05。単勝回収率 83% でいちばん良い)・夏(6〜8月)の牝馬(1.07)・
  前走7〜9番人気(1.04)。少ない = 50倍以上(0.83・回収率 58%)・6歳(0.83)・追込(0.91)・夏の牡馬(0.90)・冬の牝馬(0.90)・前走1着(0.90)・
  前走1番人気(0.91)・連闘と中1週(0.92)・半年以上の休み(0.90)・前走と同じ場(0.94)・モデルの確率が1位なのに5倍以上(0.86)。
  枠・逃げ先行差し・距離の延長短縮・芝ダ替わり・道悪の実績・巻き返し(前走人気で大敗)・小回り×脚質は、オッズの見込みとほぼ同じ
- **買い方には使えない**: 2022〜2024年で3年そろってずれた30の条件をまとめた式で、2025〜2026年の勝ち馬はオッズだけより当たらない
  (対数尤度 −0.14433 / −0.14437)。見込みの1.2倍以上と出た馬を単勝で買うと 2025年 100%・2026年 89%(大きい3つを除くと 89%・77%)。

- **実際には 3〜8時間遅れることがある**(2026-11-08 は午後の分が 19:38 に始まり、2026-11-14 は朝の分が昼になっても始まらず手で起こした)。

  (開催日の 8:40〜17:30 は45分、それ以外は13時間を超えたら)。失敗したときは GitHub からメールも届く
- このリポジトリ(公開)は、60日間なにも更新が無いと GitHub が時刻指定の実行を止める。毎日の更新が自動で入るので止まらない

## 期待値(単勝・ワイド。2026-10-25 から)

アプリのレースの欄の「期待値(単勝・ワイド)」と、全馬の評価の表の人気の下(「期0.80」)、「買い目を作る」の単勝・ワイドに出す。
期待値 = 当たる確率 × オッズ(1を超えれば、続けて買うと得になる見込み)。

- **1着の確率**: P ∝ q^a × (p3/(1-p3))^b(q=単勝オッズから出る市場の確率、p3=モデルの3着内の確率)。
  2024・2025年で a=1.00・b=0.04 に決まり、ほぼ市場の確率(`python tools/experiments/ev_fit.py`)。2026年で確かめると、
  確率の帯ごとに予想と実際がそろう(例: 20〜30% と出した馬は実際 23.6%)

    2024・2025年には 76% / 82% だった

- **確かめ方**: 月ごとに、その月より前だけで学んだモデルの確率(`keiba/model_wf.json.gz`)を作り、

### タイム指数(`keiba_speed.py`)

1kmあたりの走破タイムを「コースの基準(競馬場・芝ダ・距離)+クラスの差+その日の馬場差+馬の力」に分け、
馬柱に載っている過去走(同じ走りを1回に数えて約19万走。ほとんどが2025〜2026年)から基準・クラスの差・馬場差を交互に求める。
指数 =(基準+馬場差−タイム)×10。+10 で1kmあたり1秒速い。上がり3Fも同じように補正する。
馬場差はその日のタイムだけで決まるので、先の結果は使わない。表(`keiba_speed.json`)は学び直しのときに作り、
まだ表に無い日の馬場差は、当日の全レースの馬柱を取ったあとに足してから予想する。

指数を足すと、3着内の当てやすさ(AUC)は 0.781 → 0.793(市場は0.81)。
同じ基準(○60%以上)のワイド1点は、月ごとの確率で 2〜8月 80% → 85%、9月〜 83% → 83%(買えるレースが3割増え)。
効いている材料の1位は、指数の3走平均(レース内の順位)になった。

### 市場と食い違う馬(試したが採らなかった)

モデルの◎○が1・2番人気と違うレースで、違う馬に「はっきりした理由」があるものだけ残すのを試した
(`tools/check_disagree.py`)。理由は、タイム指数が人気馬より上・上がりの指数が上・人気馬に延長/昇級/休み明け/
斤量増/脚質の不利、など。厳しくしても(タイム差2以上かつ上がり差3以上、人気馬の減点2つ以上 など)、
理由のある食い違いのワイドは 9月〜で 61〜77% と、理由の無いものと変わらず、1・2番人気より悪かった。
モデルと1・2番人気が一致したレースだけ買うと 87% / 86%(2〜8月 / 9月〜)で、市場とほぼ同じ。
モデルは「どのレースを買うか」を選ぶのは得意だが、同じレースで2頭を選ぶのはまだ市場に届かない(特に中央)。

学び直し・確かめ: `python tools/train_model.py`(成績を出すだけ)/ `--save`(保存)/ `--walkforward`(月ごとの確率)。
買い方の比較: `python tools/simulate.py`。

## 流れ

1. 全レースから、強い2頭がいるレースだけを選ぶ(A / B)。1強・混戦・少頭数・新馬は見送り
2. 来ない馬の負け要因(距離・展開・枠・斤量・休み明け・クラス差・馬場・コース)で減点。重い減点が3つ重なった馬は消す
3. 残った馬から◎○を決める。距離延長の馬は軸にしない。◎○の弱点が同じ(両方逃げ・両方道悪苦手など)なら○を替え、替えられなければ見送り
4. 3連複は◎○2頭軸流し、3連単は◎⇄○の1・2着入れ替え
5. 馬連・ワイド◎-○で別の着順もカバーし、○-相手のワイドで◎が飛んだときに備える
6. 3頭目に人気薄(☆)を入れる

能力は過去5走の着差とクラスから作り、**人気・オッズは使わない**。オッズは評価ができたあとに
人気との食い違い(過剰人気? / 妙味)を見るだけ。アプリの全馬の評価の表には人気・オッズも出す。

閾値(2強の差・消しの基準・点数)は `keiba_logic.py` の `TH` にまとめてある。
「収支・分析」で条件別の回収率、印ごとの3着内率、減点理由ごとの3着内率(負けパターン)を見て締めていく。

## 過去の日を見る

- **レース画面** … 日付を押すとカレンダーが開き、その日の予想・買い目・結果を見られる(◀ ▶ で前後の日)
- **収支・分析** … 期間(7日 / 30日 / 今月 / 今年 / 全期間)で絞って、累積収支・カレンダー・券種別・条件別・
  印の成績・負けパターン・日別・買ったレースの明細を見る。行を押すとその日・そのレースへ飛ぶ

アプリを動かす前の日は、Actions の「**過去の日を再現**」を手動でまわすと作れる(既定は2026年1月1日〜昨日)。
日付を最大20個のジョブに分けて同時に走らせ、各ジョブの中でも1日のレースを並列に取る
(netkeiba が混んだら待ってやり直す)。最後に1回だけまとめて保存する。
その日の出馬表と「そのレースより前の過去走」だけで予想し、結果・払戻と照合する。
済んだ日は飛ばすので、途中で止まってももう一度まわせば続きから再現する。

再現した予想には「再現」と印が付き、収支画面で「当日の予想」と分けて見られる。
再現では人気に確定人気を使う(当日の予想は朝〜発走前のオッズ)。人気は穴馬(☆)選びにしか使わないので、
◎○と買うレースの選び方は当日と同じ。

取得がおかしいときは Actions の「取得の診断」をまわすと、netkeiba の応答の形がログに出る(何も保存しない)。
ロジックや閾値を変えたら、Actions の「再現の予想を作り直す」をまわすと、保存してある馬柱から
再現の予想を今のロジックで作り直す(netkeiba からは取らない。当日の予想は書き換えない)。

## コース傾向(中央10場・78コース)

[titanic-online.com「競馬場の特徴」](https://www.titanic-online.com/category/racetrack/)の各記事
(2021〜2025年の集計)から、コースごとの脚質別・枠順別・人気別の成績と、
脚質傾向・枠順傾向・ペース傾向・向いている馬/向かない馬を `keiba_course.json` にまとめて使う。

- **脚質** … そのコースの逃げ・先行・中団・後方の3着内率を、芝/ダートの全コース平均と比べる
  (脚質はレース後に決まる位置取りなので、どこでも前の馬の成績が良く出る。平均との比で「このコースで得か」を見る)。
  得なら最大+3、損なら最大-4。大きな損は ◎○ の「弱点の重なり」にも数える
- **枠** … 枠番別の3着内率を平均と比べて±2.5まで(このとき一般の枠の決まりは使わない)
- **堅さ** … 1・2番人気の3着内率が平均より高い「堅い」コースは2強の基準を0.5下げ、「荒れやすい」コースは0.5上げて穴馬を2頭まで拾う
- 出走が少ないコースは平均に寄せて控えめに効かせる。記事に無い距離はその場の芝/ダート全体を半分の重みで使う
- 地方は下の「地方のコース傾向」

例: 新潟芝1000(千直)は8枠が平均の1.6倍・1枠が0.6倍。函館・小倉・福島のダ1700は後方が平均の半分以下。
東京芝2400・阪神芝1800は後方が1.7倍以上(差しが届く)。

作り直すとき: Actions の「記事を読む」(read)で記事の本文をログに出し、
`python tools/parse_course.py 出力.json 記事.txt ...` で取り出す(記事は海外からは読めないので Wayback Machine 経由)。

## 地方のコース傾向(14場・84コース。2026年10月〜)

[うまめし.com「地方競馬特徴･攻略･傾向」](https://www.umameshi.com/info/keibajou/chihou-keiba-hisshouhou.html)と、
そこからたどれる各競馬場・各距離の記事(地方14場の本文と97ページ)を読み、`keiba_course_nar.json` にまとめた。

- **数字** … 枠番別・人気別・脚質別(そのレースでの位置取り)の集計。記事によって人気別の「着外」が出走数そのものに
  なっているので、同じ行の複勝率に合う方を出走数にしている
- **説明** … 記事を読んで、各場・各距離の特徴を短くまとめたもの(記事の文をそのまま写したものではない)。アプリのコース傾向欄に出す
- **使い方** … 中央と同じ。脚質は地方全体の平均との比で加減点、枠は枠番別の3着内率の比で±2.5まで。
  記事に数字の無い距離は場全体の数字を使う(地方は場全体の枠の傾向も使い、一律の「地方の1枠 -2」は数字が無いときだけ)
- **場のずれ** … 同じ馬が別の場で続けて走ったときのタイム指数の差から、場ごとの目盛りのずれを求めて指数に足す
  (`keiba_speed.fit_levels`。記事の「地方競馬レベル順と力関係」「名古屋と笠松のタイム差」の考え方)。
  並びはおおむね 中央 > 大井・船橋 > 門別・川崎・園田・姫路・浦和・名古屋 > 佐賀・笠松・水沢・盛岡・金沢(高知は指数が低めに出る場で、上乗せが大きい)
- **移籍など** … 中央からの移籍(前走が中央)・中央を走った割合・前走と同じ場か・走った場の数・高知のファイナルレースをモデルの材料にする

記事から読み取ったおもな傾向: 川崎は内枠、船橋・園田1400・姫路・笠松・名古屋920/1500は外枠が有利。
浦和は逃げ切りが多く1600は外枠がとても不利。高知・佐賀はインの砂が深く1枠が不利(高知は2〜3枠が良い)。
盛岡は坂と長い直線で距離が延びるほど差しが届く。金沢は先行争いが激しい。門別は内枠がやや不利で、
冬の休み明け(開幕直後)は他場で使われていた馬が有利。

確かめ(月ごとに、その月より前だけで学んだモデル): 地方のAUC 0.797 → 0.804。
○75%以上のワイド1点は 2〜8月 509R 91% → 577R 91%、9月〜 96R 92% → 118R 96%(地方だけで98%)。

作り直すとき: Actions の「記事を読む」で links(リンク集め)と read(本文)をまわし、
`python tools/parse_course_nar.py keiba_course_nar.json 記事.txt ...`。`KEIBA_NAR_COURSE=0` で地方の傾向を切って比べられる
(切り替えたらモデルを学び直す)。
