GitHub の時刻指定の実行は 3〜8時間遅れることがあり、開催日にオッズが古いままになる(2026-11-14 は朝の更新が昼まで始まらなかった)。
競輪(`honda1986/keirin` の `pc/`)と同じく、PC のタスクスケジューラが1分おきにオッズを取って `odds-live` ブランチへ送る形を作り始めた。

| ファイル | 何をするか | 状態 |
|---|---|---|
| `odds.js` | 発走まで35分以内の中央のレースの、単勝・ワイド・3連複(組ごとの強さ)を netkeiba から取り、`latest.json` と `snap/日付.json` を作る | できている(にせのサーバーで確かめた。本物の netkeiba では未確認) |
| `runner.js` | タスクスケジューラから1分おきに呼ばれ、`odds.js` を動かして `odds-live` ブランチへ送る(いつも1コミットだけ) | できている(手元の git で確かめた) |
| `selftest.js` | 読み取りと時刻の計算の自己テスト(`node pc/selftest.js`) | 6個とも通る |
| 入れる手順(`install.ps1`・タスクの登録) | 競輪の `pc/install.ps1` と同じ形の1行インストール | **まだ作っていない** |
| アプリが `latest.json` を読む・GitHub の更新が `snap/` を取り込む | | **まだ作っていない** |

**止めている理由(2026-11-14)**: いちばんの目的だった「割安ワイドを新しいオッズで選ぶ」が、同じ日の実戦で使えないと分かった
(発走の1〜10分前のオッズで選んだ16レースが全部外れ。選んだ組の期待値は確定オッズでは平均 0.87 に下がる。README の
「市場が見落としている情報を探した」の 6)。オッズを新しくしても買い目は良くならないので、続けるかどうかは決めてから。
